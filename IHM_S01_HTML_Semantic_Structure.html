01
How the Web WorksClient, server and the Document Object Model




When a user enters a URL, the client (the browser) issues an HTTP request to a server, which responds with a plain-text resource: the HTML document. The browser then parses this text sequentially and constructs an in-memory tree representation called the Document Object Model (DOM). Styles (CSS) are matched against this tree to produce the render tree, scripts (JavaScript) may modify it, and the result is finally laid out and painted on screen.


Separation of concernsHTML describes the structure and meaning of content; CSS governs its presentation; JavaScript defines its behaviour. Maintaining this separation is a foundational principle of well-engineered human-machine interfaces.

Every element becomes a node with a parent, children and siblings; even the text inside an element is a distinct text node. These relationships will be exploited in Session 11 to traverse and manipulate the page with JavaScript.







02
The HTML5 Document SkeletonDoctype, root element, head and body




A conforming HTML5 document begins with a document type declaration, followed by a single root element html containing exactly two children: head, which holds metadata addressed to the browser and to search engines, and body, which holds the rendered content.






Element / attributePurpose


<!DOCTYPE html>Triggers standards mode rendering instead of the legacy quirks mode.


lang="en"Declares the primary language; affects screen-reader pronunciation, hyphenation and spell-checking. Use dir="rtl" for Arabic.


meta charset="UTF-8"Declares the character encoding; must appear within the first 1024 bytes, hence first in head.


meta name="viewport"Maps the layout viewport to the device width: a prerequisite for responsive design.


meta name="description"A concise summary frequently displayed as the snippet in search-engine results.


titleMandatory. Used for the browser tab, bookmarks, history and search results.




Common errorPlacing rendered elements such as h1 or img inside head. The parser silently relocates them to body, but the document becomes non-conforming.







03
Content CategoriesBlock-level, inline and the HTML5 content models




Block-level behaviour


  • Starts on a new line and expands to the full available width.
  • May contain both block and inline content.
  • Examples: div p h1 section ul


Inline behaviour


  • Flows within a line and occupies only the width of its content.
  • Should not contain block-level elements.
  • Examples: span a strong em code






Advanced note: content modelsThe HTML5 specification no longer defines "block" and "inline" as categories. It instead uses content categories: flow, phrasing, sectioning, heading, embedded and interactive. Each element specifies which categories it may contain. For instance, a has a transparent content model and may therefore wrap an entire block, provided its parent permits it. Visual block/inline behaviour is now strictly a CSS concern (the display property).





04
Semantic Sectioning ElementsMeaning over appearance




A semantic element describes the meaning of its content rather than its appearance. A div conveys nothing, whereas nav informs browsers, assistive technologies and crawlers that the region contains navigation. The benefits are measurable: improved search-engine indexing (SEO), landmark navigation for screen-reader users, and more maintainable code. Hover over each region:




<header>
<nav>


<main><article><section>


<aside>
<footer>




Hover over a region of the layout to display its formal definition.








ElementCorrect usage


articleA self-contained composition, independently distributable or reusable: a blog post, a news item, a product card, a user comment.


sectionA thematic grouping of content, which should normally have a heading.


figure / figcaptionSelf-contained illustration (image, chart, code listing) with an associated caption.


timeA date or time, made machine-readable through the datetime attribute.


addressContact information for the author or owner of its nearest article or of the document.




Decision rule: article or section?Ask whether the fragment would remain meaningful if syndicated alone on another website. If so, it is an article; otherwise, a section. If the wrapper exists solely for styling and carries no meaning, a div is the correct choice.









05
Text-Level SemanticsHeadings, emphasis, quotations and entities




The heading hierarchy h1 to h6


Headings define the document outline, much like the table of contents of a book. Professional practice recommends a single h1 expressing the page topic, followed by a strictly descending hierarchy without skipped levels (an h2 followed directly by an h4 is an error). Never select a heading level for its font size: size is a presentational concern handled by CSS.






Semantic versus presentational

06
Global AttributesThe bridge between HTML, CSS and JavaScript




Global attributes may be specified on any HTML element. They constitute the interface through which stylesheets and scripts address the document.




id
A unique identifier within the document; target of fragment links and scripts.


class
A reusable classification shared by many elements; the primary CSS hook.


data-*
Custom, author-defined data read by scripts: data-price="1200"


title
Advisory information, shown as a tooltip on hover.


hidden
Indicates the element is not yet, or no longer, relevant.


tabindex
Controls focusability and sequential keyboard navigation.








Professional conventionsConsistent indentation (two or four spaces); lowercase element and attribute names; attribute values in double quotes; comments <!-- --> delimiting major regions; and systematic validation with the W3C Markup Validation Service.

EX 02
From div soup to semantic structure
Intermediate


The following markup of an online shop relies exclusively on div elements. Rewrite it with appropriate semantic elements without altering the content, and justify each choice.






JustificationThe product card is an article because it is self-contained and syndicatable. The product list is a section: a thematic group with a heading. "Recently viewed" is tangential, hence aside. The image and its caption form a figure; the update date becomes a machine-readable time.




EX 03
An economics article with precise text semantics
Intermediate


Write a short article titled "E-commerce in Algeria" inside an article element. It must contain:


  • An article header with title, author and a machine-readable publication date.
  • At least two expanded abbreviations (for example B2C and EPT).
  • One statement of strong importance, one stress emphasis that alters meaning, and one highlighted phrase.
  • A block quotation with its source, a warehouse area in square metres, and a struck-through former price next to the new price.
