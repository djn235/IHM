Absolute and Relative PathsHow the browser resolves a reference




Absolute URL


A complete locator including the scheme; required for links to external sites: https://www.mf.gov.dz/


A path beginning with / is root-relative: it is resolved from the root of the current site, e.g. /images/logo.png.


Document-relative path


Resolved from the directory of the current document; used within the same site.


  • page.html same directory
  • images/logo.png a subdirectory
  • ../index.html one level up
  • ../../css/style.css two levels up

Critical path errorsWindows back-slashes \ instead of /; local file-system paths such as C:/Users/... that cannot work on a server; spaces and non-ASCII characters in file names; and case mismatches: Logo.PNG and logo.png are distinct files on Linux servers.

Advanced HyperlinksThe anchor element




The a element is the essence of hypertext. Its href attribute accepts several categories of destination:




TypeSyntaxUse case


Internal pagehref="contact.html"Navigation between pages of a site


Fragmenthref="#pricing"Jump to the element with id="pricing"


Page + fragmenthref="faq.html#payment"A specific section of another page


E-mailhref="mailto:a@b.dz?subject=..."Opens the mail client with a pre-filled subject


Telephonehref="tel:+213..."Direct call on mobile devices


Downloadhref="x.pdf" downloadDownloads the resource instead of navigating to it










Security: target="_blank"A link opening a new browsing context should carry rel="noopener noreferrer", which denies the new page access to window.opener and thereby prevents reverse tabnabbing. Modern browsers imply noopener, yet declaring it remains good practice.


Accessibility: link textAvoid "click here" and "read more". Screen-reader users frequently navigate a list of links extracted from context; the text must describe the destination, e.g. "Download the student guide (PDF, 2 MB)" (WCAG 2.4.4).







04
Images and Format SelectionThe img element




img is a void element (no closing tag) with two required attributes: src, the image URL, and alt, a text alternative conveyed to users of assistive technologies and displayed when the image fails to load.




width / height
Reserve the image's box before it loads, preventing layout shift (the CLS metric).


loading="lazy"
Defers fetching until the image approaches the viewport.


decoding="async"
Decodes off the main thread without blocking rendering.






FormatPropertiesOptimal use


JPEGLossy compression, millions of coloursPhotographs


PNGLossless, alpha transparencyScreenshots, sharp-edged graphics


SVGVector, resolution-independent, scriptableLogos, icons, diagrams


WebPTypically 25-35% smaller than equivalent JPEGModern default for most images


AVIFHighest compression currently availableLarge images, with a fallback








Writing alt textFor an informative image, describe the information it conveys ("Sales curve 2020-2025 showing a 40% rise"). For a purely decorative image, use an empty alt="" so that assistive technologies ignore it. Do not begin with "Image of...": screen readers already announce the role.





05
Responsive Imagessrcset, sizes and picture




Sending a 2000-pixel-wide image to a 400-pixel phone screen wastes bandwidth, time and energy. HTML5 provides two mechanisms for two distinct problems:




A
Resolution switching: the same image in several sizes; the browser chooses via srcset and sizes.


B
Art direction and format selection: different crops per layout, or modern formats with fallback, via picture and source.










How the browser evaluates sizes


sizes="(max-width: 600px) 100vw, 50vw" states: if the viewport is at most 600 px wide, the image occupies the full viewport width; otherwise half of it. The browser multiplies this slot width by the device pixel ratio and selects, from srcset, the smallest candidate that satisfies the requirement. The descriptor 800w declares the intrinsic width of that file.


Worked example. On a 390 px phone with a pixel ratio of 3, the slot is 390 px, so 390 × 3 = 1170 physical pixels are needed: the 1600w candidate is chosen. On a 1440 px laptop at ratio 1, the slot is 720 px: the 800w candidate suffices.






Source order mattersThe browser evaluates source elements top-down and uses the first match. List modern formats first (AVIF, then WebP). The final img is mandatory: it carries alt and is the fallback for older browsers.





06
Native Audio and Videoaudio, video and track




Before HTML5, playback required third-party plug-ins such as Flash. Browsers now ship native media players configured through attributes:




AttributeFunction


controlsDisplays the native play, volume and full-screen controls.


autoplay mutedAutoplay is permitted by browser policies only when muted.


loopRestarts playback at the end.


posterCover image shown before playback (video only).


preloadnone, metadata or auto: how much to fetch in advance.


playsinlineInline rather than full-screen playback on iOS.








Captions with trackA WebVTT file pairs text with timestamps. Captions are essential for deaf and hard-of-hearing users (WCAG 1.2.2), useful in sound-off environments, and improve the indexability of video content.





07
Embedding Third-Party Contentiframe and security




The iframe element nests a complete browsing context in your page: a map, a hosted video, a payment form. Because it introduces third-party code, it must be constrained.


    

  • title is required for accessibility: it names the frame for screen readers.
    • 

  • loading="lazy" defers heavy frames.
    • 

  • sandbox applies all restrictions; tokens such as allow-scripts then lift only those required (principle of least privilege).
    • 

  • allow delegates permissions: full screen, camera, geolocation.
    • 

  • referrerpolicy controls what referrer information is disclosed.
    • 







Not every site can be framedMany sites (banks, social networks) forbid framing through the X-Frame-Options header or the CSP frame-ancestors directive, protecting their users against clickjacking. Platforms therefore provide dedicated "embed" URLs.
