Part A: FoundationsExercises 1 and 2


EX 01
Product variants and favourites
Foundational20 min


A product card for a T-shirt offers three colour swatches (Navy, Sand, Forest). Write the script so that:


  • clicking a swatch updates the product image background, the text "Colour: ..." and the reference (e.g. TS-NAV), read from data-* attributes of the swatch;
  • the selected swatch is marked with aria-pressed="true" (and the others with false) and styled from that attribute;
  • a "Add to favourites" button toggles its state, its text and a .fav class on the card.


Use a single delegated listener for the three swatches.






EX 02
A quantity stepper
Foundational20 min


Build a quantity stepper for a cart line: a "−" button, a numeric input and a "+" button, with a unit price of 2 750 DZD. Requirements:


  • the quantity stays between 1 and 10; the buttons are disabled at the limits;
  • typing directly in the input is also handled (invalid or out-of-range values are corrected when the field loses focus);
  • the line total is updated immediately, formatted in DZD, and announced in a live region;
  • the buttons have accessible names ("Decrease quantity", "Increase quantity").

EX 03
A searchable staff directory
Intermediate30 min


Render the employees below as cards using a template element. Add a search field (matching name or role, case-insensitively and ignoring accents if you can), a department filter populated from the data (distinct departments), and a counter "n of m employees" in a live region. Clicking a card's "Call" button must log the employee's phone number, using a single delegated listener on the list. User data must never be inserted with innerHTML.

EX 04
Accessible tabs
Intermediate30 min


Implement a tabs component for a customer record (Overview, Orders, Invoices) following the WAI-ARIA Tabs pattern:


  • roles tablist, tab and tabpanel, with aria-controls, aria-labelledby and aria-selected;
  • only the active tab is in the tab sequence (tabindex="0"), the others have tabindex="-1";
  • ArrowLeft/ArrowRight move between tabs (wrapping around), Home/End go to the first/last tab;
  • inactive panels are hidden with the hidden attribute, and the selected tab is remembered in the URL fragment so that a reload restores it.

Part C: MasteryExercises 5 and 6


EX 05
Live registration validation
Advanced35 min


Enhance a registration form (username, e-mail, password, password confirmation) with live validation:


  • username: 4 to 15 characters, letters, digits and underscores only, and not already taken (simulate with the list ["admin", "amina", "karim"]);
  • password strength meter (weak / medium / strong) based on length, digits, upper-case letters and symbols, displayed with a meter element and a text;
  • confirmation must match the password, enforced with setCustomValidity();
  • messages appear after the user has left a field (not while they type their first character), are linked with aria-describedby, and set aria-invalid;
  • on submit, prevent sending if anything is invalid, focus the first invalid field, and show an error summary; otherwise display a success message.






EX 06
A modal dialog for adding a supplier
Advanced35 min


Using the native dialog element, create a modal "New supplier" form opened by a button on a supplier list page:


  • open it with showModal(); the first field receives the focus; the page behind is inert;
  • close it with a "Cancel" button, the Escape key, or a click on the backdrop;
  • the form uses method="dialog"; on confirmation, the new supplier is appended to the list (rendered with textContent), and a status message is announced;
  • on closing, the focus returns to the button that opened the dialog;
  • an entrance animation that respects reduced motion.




Why the native dialog?showModal() provides, without extra code, a top-layer rendering, an inert background, Escape handling and correct focus containment, which are difficult to implement correctly with a div. The returnValue of the dialog tells which button closed it.
