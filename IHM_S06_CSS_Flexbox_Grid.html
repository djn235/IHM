Modern Layout:

Two complementary layout models replaced floats and tables: Flexbox distributes space along one axis, Grid organises content in two dimensions. This session formalises their algorithms and applies them to the layouts of business applications.

01
From Normal Flow to Layout Modelsdisplay, axes and dimensions




By default, boxes are laid out in normal flow: block boxes stack vertically, inline boxes flow horizontally within lines. Historically, multi-column interfaces were obtained by diverting floats and tables from their purpose. Modern CSS provides dedicated layout models, activated through the display property of a container, which then governs its direct children, the items.




Flexbox display: flexGrid display: grid


DimensionsOne: a row or a columnTwo: rows and columns simultaneously


Driven byContent: items negotiate their sizesContainer: tracks are defined first, items placed into them


Typical useComponents: toolbars, menus, card internals, centringPage structure, galleries, dashboards, forms

Main axis and cross axisIn Flexbox, flex-direction defines the main axis; the cross axis is perpendicular to it. justify-content always acts on the main axis and align-items on the cross axis. This is why "vertical centring" depends on the direction chosen.

03
Flex Items and Space Distributionflex-grow, flex-shrink, flex-basis




Each item has a hypothetical main size, its flex-basis. The algorithm then computes the free space of the line, i.e. the container size minus the sum of the bases and gaps:


    

  • If it is positive, it is shared out in proportion to the flex-grow factors.
    • 

  • If it is negative (overflow), the deficit is absorbed in proportion to flex-shrink × flex-basis, so that large items shrink more than small ones.
    • 



Worked exampleContainer 900px; three items with flex: 1 1 200px, flex: 2 1 200px, flex: 1 1 100px. Free space = 900 − 500 = 400px; grow factors sum to 4, so one unit = 100px. Final widths: 200+100 = 300, 200+200 = 400, 100+100 = 200.




ShorthandExpands toBehaviour


flex: initial0 1 autoSized by content; may shrink, never grows (the default)


flex: 11 1 0%Equal shares of the container, regardless of content


flex: auto1 1 autoGrows and shrinks from its content size


flex: none0 0 autoRigid: keeps its content size




order changes the visual order and align-self overrides align-items for one item. Caution: order does not change the keyboard and reading order, so visual and logical sequences may diverge (WCAG 1.3.2).









04
The Grid Containertracks, fr, repeat() and minmax()




A grid is defined by its tracks (columns and rows) separated by numbered lines. The fr unit represents a fraction of the free space remaining after fixed tracks are sized. repeat() avoids repetition, minmax(min, max) constrains a track between bounds, and auto-fill / auto-fit create as many tracks as fit: the basis of intrinsically responsive grids.

Line-based placementgrid-column: 1 / -1 stretches an item from the first to the last line, whatever the number of columns. span n sets a size without fixing a position. grid-auto-flow: dense back-fills holes left by large items, at the cost of the visual order.




auto-fill versus auto-fitBoth create as many columns as fit. When there are fewer items than columns, auto-fill keeps the empty tracks, whereas auto-fit collapses them so that the existing items stretch to fill the row.





05
Named Template Areasgrid-template-areas




grid-template-areas describes a layout as an ASCII map in which each string is a row and each name a cell. Items are assigned to areas with grid-area. The layout becomes self-documenting, and rearranging it for another screen size only requires redefining the map (Session 07).

Choosing the Right ModelDecision criteria and patterns






PatternRecommended modelCore declarations


Centring an elementGrid or Flexboxdisplay:grid; place-items:center


Navigation barFlexboxjustify-content:space-between; align-items:center


Card with button at the bottomFlexbox (column)flex-direction:column + margin-top:auto on the button


Product galleryGridrepeat(auto-fill, minmax(220px,1fr))


Application shellGridgrid-template-areas


Sticky footerGridmin-height:100vh; grid-template-rows:auto 1fr auto




Guiding principleUse Grid when you can draw the layout as a two-dimensional map before knowing the content; use Flexbox when the content should determine how space is shared along a line. Professional interfaces combine both: a Grid page whose components are Flexbox containers.

Practical ExercisesAlign, distribute, compose


EX 01
Responsive navigation bar
Foundational


Build the header of an online bank: the logo on the left, four navigation links in the centre group, and a "Log in" button on the right. Items must be vertically centred, the links separated by a 1.5rem gap, and the bar must wrap gracefully on narrow screens. Use a semantic nav with a list.






EX 02
Adaptive product catalogue
Intermediate


Create a catalogue of six product cards that displays as many columns as fit (minimum card width 220px) without any media query. Inside each card (image, title, description of variable length, price, button), the button must always be aligned at the bottom of the card, whatever the description length.






EX 03
Management dashboard
Intermediate


Using grid-template-areas, build the shell of a sales dashboard: header across the top, a 220px sidebar, a main area containing four KPI tiles on one row, a chart spanning three tiles and a "top products" panel beside it, and a footer. The whole layout must fill at least the viewport height.






EX 04
Computing the flex algorithm
Advanced


Three items have flex: 1 1 200px, flex: 2 1 100px and flex: 1 3 300px, with no gap.


  1. Compute their widths in a container of 800px.
  2. Compute their widths in a container of 500px.
  3. Verify both results with the code below and the DevTools.





1. 800px: bases = 200 + 100 + 300 = 600; free space = +200; grow sum = 1 + 2 + 1 = 4; unit = 50px

  widths = 200+50 = 250, 100+100 = 200, 300+50 = 350 (total 800)

2. 500px: free space = −100; scaled shrink factors = 1×200, 1×100, 3×300 = 200, 100, 900 (sum 1200)

  reductions = 100×200/1200 = 16.67, 100×100/1200 = 8.33, 100×900/1200 = 75

  widths = 183.33, 91.67, 225 (total 500)
