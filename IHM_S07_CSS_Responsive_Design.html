01
Principles of Responsive DesignFluid grids, flexible media, media queries




The term responsive web design was coined by Ethan Marcotte in 2010. Rather than building separate sites for each device class, a single document adapts its presentation according to the characteristics of the rendering context. The approach rests on three pillars:




1
Fluid grids
Dimensions expressed in relative units (%, fr, rem) rather than fixed pixels.


2
Flexible media
Images and videos that never exceed their container: max-width: 100%.


3
Media queries
Conditional rules that modify the layout at chosen breakpoints.








Mobile-first strategy


A mobile-first stylesheet first defines the simplest layout, the single column suited to small screens, then adds complexity for wider viewports with min-width queries. This approach, formulated by Luke Wroblewski, has three advantages: the essential content is prioritised; small devices, often on slower networks, download and evaluate fewer overriding rules; and the code is easier to reason about, since each breakpoint only enriches the previous one.


PrerequisiteThe <meta name="viewport" content="width=device-width, initial-scale=1"> declaration seen in Session 01 is mandatory. Without it, mobile browsers lay the page out at a virtual width of about 980px and shrink it, so that no media query targeting small screens ever applies.







02
Media QueriesConditional rules and breakpoints




A media query applies a block of rules only when its conditions are met. Level 4 introduced a range syntax that is more readable than the traditional min-/max- prefixes and is supported by all current browsers.




FeatureExampleUse


Width@media (width >= 768px) = (min-width: 768px)Layout breakpoints


Range@media (600px <= width < 1024px)Targeting an interval


Orientation(orientation: landscape)Tablet-specific adjustments


Interaction(hover: hover), (pointer: coarse)Hover effects only with a mouse; larger touch targets on touch screens


Preferences(prefers-color-scheme: dark), (prefers-reduced-motion: reduce)Respecting operating-system settings


Media type@media printPrint-friendly invoices and reports




Choosing breakpointsBreakpoints should be dictated by the content, not by a list of fashionable devices: widen the window until the layout looks wrong (lines too long, cards too stretched), and place a breakpoint there. Typical values (around 600, 900 and 1200px) are only a starting point. Expressing them in em makes them respect the user's text zoom.

03
Fluid Techniquesclamp(), min(), max(), aspect-ratio and flexible media




Breakpoints produce discrete jumps. Fluid techniques complement them with continuous adaptation, often removing the need for many media queries.




Function / propertyMeaningExample


min(a, b)The smaller valuewidth: min(100% - 2rem, 70ch)


max(a, b)The larger valuepadding: max(1rem, 3vw)


clamp(min, ideal, max)The ideal value, boundedfont-size: clamp(1rem, .8rem + 1vw, 1.5rem)


aspect-ratioFixed proportions without a fixed sizeaspect-ratio: 16 / 9


object-fitHow a replaced element fills its boxobject-fit: cover








Fluid typography calculator


A fluid size grows linearly between two viewport widths. Given a size range and a viewport range, the slope and intercept of the line yield the clamp() expression. The rem intercept preserves user zoom, satisfying WCAG 1.4.4.



















04
Container QueriesComponent-level responsiveness




Media queries respond to the viewport, yet a component may be placed in a narrow sidebar on a wide screen. Container queries allow a component to adapt to the size of its own container, making it genuinely reusable. The ancestor is declared with container-type: inline-size, and the rules are written in an @container block. Container query units (cqi, cqw) express sizes relative to that container.






Viewport or container?Use media queries for the overall page layout (the shell), and container queries for components that appear in contexts of varying width (cards, widgets, form groups).





05
User Preferences and Robust PatternsDark mode, reduced motion, tables, touch targets




    

  • Colour scheme: with design tokens declared as custom properties (Session 05), dark mode only requires redefining the tokens inside @media (prefers-color-scheme: dark).
    • 

  • Reduced motion: users with vestibular disorders can request minimal animation; respecting prefers-reduced-motion is an accessibility obligation (WCAG 2.3.3).
    • 

  • Wide tables: wrap them in a container with overflow-x: auto rather than letting the page scroll horizontally (WCAG 1.4.10 Reflow).
    • 

  • Touch targets: at least 24 × 24 CSS pixels (WCAG 2.5.8), and preferably 44 × 44 on (pointer: coarse) devices.
    • 

  • Print: hide navigation and decorations, and reveal link URLs with a::after { content: " (" attr(href) ")"; }.
    • 







Testing methodologyUse the device toolbar of the DevTools (Ctrl+Shift+M), emulate prefers-color-scheme and prefers-reduced-motion in the Rendering panel, zoom the text to 200%, and always confirm on at least one physical phone. Lighthouse provides an automated audit of mobile performance and accessibility.





06
Practical ExercisesAdapt, scale, reorganise


EX 01
Mobile-first service grid
Foundational


Write a mobile-first stylesheet for a section of six service cards: one column by default, two columns from 600px, three columns from 1000px. The section heading must be centred from 600px onwards, and the outer padding must increase at each breakpoint. Use only min-width queries (or the range syntax) and test your solution with the "Edit live" mode.






EX 02
Deriving a fluid type scale
Intermediate


The design team specifies a main heading of 24px on a 320px screen and 48px on a 1200px screen, and a body text of 16px to 19px over the same range.


  1. Compute the slope and intercept for each size and write the two clamp() declarations.
  2. Verify your results with the calculator of section 03.
  3. Explain why the intercept must be expressed in rem rather than in pixels.




Headingslope = (48 − 24) / (1200 − 320) = 0.02727, i.e. 2.727vw; intercept = 24 − 0.02727 × 320 = 15.27px = 0.955rem.
font-size: clamp(1.5rem, 0.955rem + 2.727vw, 3rem);


Body textslope = (19 − 16) / 880 = 0.00341, i.e. 0.341vw; intercept = 16 − 0.00341 × 320 = 14.91px = 0.932rem.
font-size: clamp(1rem, 0.932rem + 0.341vw, 1.1875rem);


Why rem?A purely vw-based size ignores the user's browser font setting and does not grow when the text is zoomed, which violates WCAG 1.4.4. Adding a rem component keeps the size proportional to the user's preference.








EX 03
Responsive management dashboard
Intermediate


Take the dashboard of Session 06 (exercise 3) and make it responsive by redefining only grid-template-columns and grid-template-areas:


  • Below 600px: a single column; the sidebar becomes a horizontal menu under the header; KPI tiles are stacked one per row.
  • From 600px to 999px: no sidebar column (menu under the header), KPI tiles in a 2 × 2 grid, the chart across the full width, top products below it.
  • From 1000px: the original layout.






EX 04
A context-aware product card
Advanced


Build a product card that is reused both in a narrow sidebar (280px) and in a wide main area (640px). Using a container query, the card must be vertical in narrow containers and horizontal (image on the left, at 40% of the width) when its container is at least 420px wide. The title size must scale with the container through cqi units. Additionally, support dark mode through tokens and disable the hover transition when reduced motion is requested.
