EX 01
A business card driven by tokens
Foundational20 min


Style the business card of a consultant (name, job title, company, e-mail, phone) so that its whole appearance depends on six tokens declared on :root: brand colour, text colour, surface colour, radius, spacing unit and font stack. Then create a variant .card.premium that changes only the token values (no other declaration) to obtain a dark card with a gold accent.


In a real project the rules would live in css/card.css linked from head; here they are embedded for the preview.




Why tokens?Because custom properties inherit, redefining them on .premium re-themes every descendant rule that uses var(). This is exactly how dark mode and white-label products are built.

EX 03
Specificity arithmetic
Intermediate20 min


Compute the specificity (a, b, c) of each selector, then rank them from the most to the least specific.






SelectorDecomposition(a, b, c)


A4 types(0, 0, 4)


B1 class + 1 pseudo-class, 1 type(0, 2, 1)


C1 id, 1 class, 1 type (the combinator counts for nothing)(1, 1, 1)


D1 attribute, 1 type + 1 pseudo-element(0, 1, 2)


E1 pseudo-class, 2 types(0, 1, 2)


F:is() takes its most specific argument #cart (1,0,0), + .item(1, 1, 0)


G:where() contributes zero, + .item(0, 1, 0)


H1 id; .dark + :not(.hidden); body, main, section, h2(1, 2, 4)


RankingH (1,2,4) > C (1,1,1) > F (1,1,0) > B (0,2,1) > D = E (0,1,2) > G (0,1,0) > A (0,0,4). D and E tie: between them, the rule declared later wins. A has four type selectors yet loses to G's single class: the comparison is lexicographic, not a sum.

EX 05
Box arithmetic for pricing cards
Advanced25 min


A pricing section of width 960px contains three cards side by side. Each card has width: 300px, padding: 24px, a 3px border and a horizontal margin of 10px on each side. Inside each card, an h3 has margin-bottom: 16px and the following paragraph margin-top: 24px.


  1. Under the default box-sizing, what horizontal space do the three cards require? Do they fit?
  2. Same question with border-box. What is the content width of each card?
  3. What is the vertical distance between the heading and the paragraph? And if the card becomes a flex container in column direction?





1. content-box: one card = 300 + 2×24 + 2×3 = 354px; with margins 354 + 20 = 374px; three cards = 1 122px > 960px: they overflow (or wrap).

2. border-box: one card = 300px; with margins 320px; three cards = 960px: an exact fit. Content width = 300 − 48 − 6 = 246px.

3. Normal flow: the adjacent vertical margins collapse: max(16, 24) = 24px. In a flex container margins never collapse: 16 + 24 = 40px.









EX 06
Generated content and state pseudo-classes
Advanced30 min


Using the markup below and CSS only, implement the following:




  1. A red asterisk after the label of every field whose input is required.
  2. An input that is invalid and no longer shows its placeholder (i.e. the user has typed something) gets a red border; once valid, a green one.
  3. Links leaving the university domain are followed by the text " (external)".
  4. The procedure steps are numbered "Step 1", "Step 2"... with a CSS counter in a coloured badge, instead of default list numbers.
  5. The first letter of the guide's first paragraph is a drop cap three lines high.
  6. Selected text appears in white on indigo.




Content in CSS: a cautionText generated with content is usually read by screen readers but cannot be selected or translated reliably. Reserve it for decorative or redundant indicators (an asterisk alongside the word "required", a "(external)" hint); essential information belongs in the HTML.
