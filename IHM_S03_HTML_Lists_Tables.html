01
Lists and Their Semanticsul, ol, li and nesting




The choice of list element is a semantic decision, not a stylistic one. The question to ask is: would changing the order of the items change the meaning?




ul Unordered list
A set of items whose order is not significant: product features, navigation menus, required documents.


ol Ordered list
A sequence where order carries meaning: procedural steps, rankings, legal clauses.






Attribute of olEffectExample


typeNumbering style: 1, a, A, i, Itype="I" for chapters


startInitial ordinal valuestart="5" continues a list


reversedDescending numberingTop-10 rankings


value (on li)Forces the ordinal of one item<li value="10">








Content model constraintThe only permitted children of ul and ol are li elements (and script-supporting elements). A nested list must therefore be placed inside an li, never directly inside the parent list.





02
Description Listsdl, dt and dd




A description list represents an association list of name-value groups: terms and definitions, metadata keys and values, questions and answers. A dt (term) may be followed by one or several dd (descriptions), and several terms may share one description.


HTML5 also allows each name-value group to be wrapped in a div inside dl, which is useful for styling groups.






Typical business usesGlossaries of financial terms, product specification sheets ("Processor: Intel i7"), invoice metadata ("Invoice no.: 2026-0451", "Due date: 30/11/2026") and frequently asked questions.





03
Table Fundamentalstable, tr, th, td and caption




A table is a two-dimensional data structure: each data cell is defined by the intersection of a row and a column, and its meaning depends on the corresponding headers. Tables must be reserved for tabular data. Using them to lay out a page, a common practice in the 1990s, is an obsolete technique that harms accessibility; layout is the role of CSS Grid and Flexbox (Session 06).




tr
Table row: a horizontal sequence of cells.


th
Header cell: labels a row or a column; bold and centred by default.


td
Data cell: holds a value.




caption, which must be the first child of table, provides the table's title. It is announced first by screen readers and allows users to decide whether to explore the table.









04
Structural Groupsthead, tbody, tfoot, colgroup and col




Row groups partition a table into a header, one or more bodies, and a footer. They convey structure to assistive technologies, allow headers and footers to repeat on each printed page, and provide hooks for styling and scripting.


    

  • thead: rows of column headers.
    • 

  • tbody: data rows. A table may contain several tbody elements to separate logical groups (e.g. operating and financial items).
    • 

  • tfoot: summary rows such as totals and averages.
    • 

  • colgroup / col: column groups, used to style entire columns (width, background) without repeating classes on every cell.
    • 










05
Cell Spanningcolspan and rowspan




colspan extends a cell across several columns; rowspan across several rows. The essential rule is the preservation of the grid: every slot covered by a spanning cell must be removed from the markup of the affected rows. Forgetting to remove them produces extra cells that overflow the grid, the most frequent error in student work.

06
Accessible Data Tablesscope, headers and id




A sighted user relates a cell to its headers visually. A screen-reader user relies on programmatic associations, so that on reaching a cell the software announces, for example, "Q2, North region, 340 000". Two mechanisms exist:




MechanismUseValues


scope on thSimple and two-header tables (the vast majority)col, row, colgroup, rowgroup


headers on td/thIrregular or multi-level tablesA space-separated list of header ids


abbr on thA short form of a long header, read repeatedlyabbr="Revenue"








Checklist for a professional data tableA descriptive caption; every header in a th with scope; row groups declared; totals in tfoot; units stated in headers ("Amount (DZD)") rather than repeated in each cell; and no empty cells used merely for spacing.

EX 02
Weekly timetable with merged cells
Intermediate


Produce the weekly timetable of a Business Computing group (Sunday to Thursday, four time slots). Requirements:


  • A caption, a header row of days, and the time slots as row headers with the correct scope.
  • The "Human-Machine Interface" lecture lasts two consecutive slots on Sunday (rowspan).
  • A "Midday break" row spans the five days (colspan).
  • Verify that each row accounts for exactly six columns.






EX 03
Accessible balance sheet
Intermediate


Model a simplified balance sheet of a company as a single table with two tbody groups (Assets and Liabilities & Equity). Each group starts with a header row spanning both columns with scope="rowgroup"; each item is a row header; amounts are right-aligned via a col; group totals and the overall total appear in tfoot.






EX 04
Multi-level sales report
Advanced


Build a table of sales by region (North, Centre, South) and by period, where the columns are grouped into two semesters (H1 and H2), each spanning two quarters. Since a data cell depends on three headers (region, semester, quarter), use id and headers to make every association explicit. Add an annual total column.




Why headers here?With two header rows, scope="col" on the quarter cells is not sufficient for every screen reader to also associate the semester. The headers attribute lists, for each td, the ids of all its headers, which makes the association unambiguous.
