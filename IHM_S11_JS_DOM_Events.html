01
The Document Object ModelA tree of objects with an API




When the browser parses an HTML document, it builds a tree of node objects (Session 01) and exposes it to scripts through the global object document. Every element node is an object with properties (id, className, textContent...) and methods (append(), remove(), addEventListener()...). Modifying these objects modifies the page immediately.




1. SelectLocate the element(s) concerned


2. ListenAttach a handler to an event


3. ComputeUpdate the data (state)


4. RenderReflect the state in the DOM








Selecting elements




MethodReturns


document.getElementById("cart")The element with that id, or null


document.querySelector(".card > h3")The first element matching any CSS selector (Session 05), or null


document.querySelectorAll("li.item")A static NodeList of all matches, iterable with for...of or forEach


element.closest(".card")The nearest ancestor (or itself) matching the selector




Traversal: parentElement, children, firstElementChild, nextElementSibling and previousElementSibling navigate between element nodes. Selections can also be scoped: card.querySelector(".price") searches only within card.

Security: textContent versus innerHTML


Type text containing markup, then a malicious payload such as <img src=x onerror="alert(1)">. Inserting untrusted input with innerHTML enables Cross-Site Scripting (XSS), one of the most common Web vulnerabilities: the attacker's code runs with the victim's privileges.

03
Creating and Removing ElementsFrom data to view




Dynamic interfaces render data: for each object in an array, an element is created and inserted. The essential methods are document.createElement(tag), then parent.append(...) / prepend(...), el.before(...) / after(...), el.replaceWith(...) and el.remove().


    

  • Inserting many elements one by one causes repeated work; build them in a DocumentFragment and insert it once.
    • 

  • The <template> element holds inert markup that is cloned with template.content.cloneNode(true), keeping structure in HTML rather than in strings.
    • 

  • A robust architecture keeps a single source of truth (the data array) and a render() function that rebuilds the view from it after every change.
    • 










04
EventsaddEventListener and the event object




An event is a notification that something has happened: a click, a key press, a change of value, a form submission, the end of page loading. A listener is registered with target.addEventListener(type, handler, options); when the event occurs, the handler receives an event object describing it.




CategoryEvent types


Pointer and mouseclick, dblclick, pointerdown, pointermove, mouseenter, contextmenu


Keyboardkeydown, keyup (with event.key)


Formsinput (every change), change (committed change), submit, invalid, reset


Focusfocus, blur, focusin, focusout


Document and windowDOMContentLoaded, load, resize, scroll




Key properties of the event object: type; target (the element where the event originated); currentTarget (the element whose listener is running); key; and the methods preventDefault(), which cancels the browser's default action (following a link, submitting a form), and stopPropagation().


Avoid inline handlersAttributes such as onclick="..." mix behaviour into markup, allow only one handler per event, and are blocked by strict Content Security Policies. Always use addEventListener.









05
Propagation and DelegationCapture, target and bubbling phases




An event dispatched on an element does not concern it alone. It travels through the tree in three phases: the capture phase, from window down to the parent of the target; the target phase; and the bubbling phase, from the target back up to window. Listeners run during bubbling by default, and during capture if registered with { capture: true }.

    Event delegation
    

    Bubbling enables a powerful pattern: rather than attaching a listener to each of a hundred buttons (including those created later), attach one listener to their common ancestor and determine the actual target with event.target.closest(selector). Delegation reduces memory use and automatically covers elements added dynamically.
    

    

    

    


    06
    Accessible Dynamic InterfacesForms, focus, live regions and persistence
    

    

      

    • Use native controls: a button is focusable and activates with Enter and Space without any extra code; a clickable div is not.
      • 

    • Reflect state in ARIA: a toggle button updates aria-pressed; a disclosure button updates aria-expanded.
      • 

    • Announce changes: messages inserted into an element with aria-live="polite" (or role="status") are read by screen readers without moving the focus.
      • 

    • Manage focus: after deleting an item or opening a dialog, move the focus deliberately with el.focus().
      • 

    • Validate helpfully: combine native constraints (Session 04) with setCustomValidity(), aria-invalid and messages linked through aria-describedby.
      • 

    • Persist preferences: localStorage.setItem(key, JSON.stringify(value)) keeps a theme or a cart between visits (wrapped in try...catch, since storage may be unavailable).
      • 

    

    

    

    


    07
    Practical ExercisesSelect, listen, render
    

    EX 01
    Theme toggle and character counter
    Foundational
    

    On a feedback page: (a) a button toggles a dark class on body, updates its aria-pressed state and its label, and remembers the choice in localStorage; (b) a textarea limited to 200 characters displays "n characters remaining", turning red below 20.
    

    

    

    EX 02
    Filterable product catalogue
    Intermediate
    

    Render an array of eight products as cards. Above the list, a search field (filtering by name as the user types, case-insensitively), a category select and a "In stock only" checkbox combine their criteria. Display the number of results in a live region, and an explicit message when no product matches.
    

    

    

    EX 03
    Task manager with delegation and persistence
    Intermediate
    

    Build a task list for a project team: a form adds a task (preventing the page reload); each task has a checkbox to mark it done and a delete button. Use a single delegated listener on the list for both actions, keep the tasks in an array as the single source of truth, re-render after each change, and persist the array in localStorage.
    

    

    

    EX 04
    Live loan calculator with validation
    Advanced
    

    Create a form (amount, annual rate, duration in months) that displays the monthly instalment and the total cost as the user types, formatted in DZD. Validate each field (amount 50 000 to 5 000 000; rate 0 to 20; duration 6 to 120): on an invalid field, set aria-invalid, show a message linked by aria-describedby, and suspend the result. On submission, prevent the default action, focus the first invalid field if any, and otherwise announce a confirmation in a live region.
