EX 01
From fixed to fluid
Foundational20 min


The landing page below was written for a 960px screen. On a phone it produces a horizontal scroll bar. Identify every fixed dimension responsible, then rewrite the stylesheet so that the page adapts to any width from 320px, without any media query: a readable centred column of at most 960px with 1rem side margins, a fluid image, two feature boxes that sit side by side when there is room and stack otherwise.

EX 02
A mobile-first navigation bar
Foundational20 min


Write a mobile-first header for a tourism agency with a logo and five links. Requirements:


  • Base (small screens): logo above, links stacked in a full-width column, each with a touch target at least 44px high.
  • From 700px: logo on the left, links in a horizontal row on the right.
  • Hover effects only on devices with a precise pointer that can hover; a visible focus style for everyone.
  • The current page is indicated with aria-current="page" and styled from that attribute.




Use Edit live and resize the preview, or open the DevTools device toolbar, to see the switch at 700px.

Part B: ApplicationExercises 3 and 4


EX 03
A responsive orders table
Intermediate25 min


An orders table with six columns (Order, Customer, Date, Items, Total, Status) is unreadable on a phone. Implement two complementary strategies:


  1. From 640px upwards: the normal table inside a scrollable, keyboard-focusable container with an accessible name.
  2. Below 640px: each row becomes a card; each cell displays its column name on the left, taken from a data-label attribute through generated content, and its value on the right. The table header is visually hidden but remains available to screen readers.




Accessibility cautionChanging the display of table elements can remove their table semantics in some browsers. The solution therefore restores the roles explicitly with role="table", role="row" and role="cell" on the elements whose display is changed.

EX 05
A product card in three contexts
Advanced30 min


The same product card component appears in three places: a 260px sidebar, a 520px content column and a 900px featured banner. Using container queries only (no media query), the card must adopt three layouts:


  • below 400px: vertical (image on top, text below), compact price;
  • from 400px: horizontal, image taking 40% of the width;
  • from 700px: horizontal with the image at 50%, a larger title scaled with cqi units, and the description visible (it is hidden in the two smaller layouts).


Name the container so that the queries target it explicitly.






EX 06
A printable, theme-aware invoice
Advanced30 min


Style an invoice page that works in three contexts:


  1. Screen, light and dark: colours defined as tokens and redefined under prefers-color-scheme: dark.
  2. Reduced motion: the "Pay now" button has a hover animation that is disabled when reduced motion is requested.
  3. Print: navigation and buttons hidden; black text on white whatever the theme; the URLs of links printed after their text; no table row split across two pages; the table header repeated on every page; A4 page margins of 15mm.


Test the print version with Ctrl+P on the opened preview, or with the DevTools Rendering panel ("Emulate CSS media type: print").
